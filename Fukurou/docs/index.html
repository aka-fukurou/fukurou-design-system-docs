Who it’s for

Designers

Use the Figma library for components, variants, and theme modes. Prefer published public sets over internal .Base pieces.

Engineers

Map to the token tiers (Foundation → Theme → Component). Mirror Active vs Focus Visible on form controls. Do not invent missing components.

Stakeholders

Track status, accessibility posture, and what is intentionally not in the system yet.

Core principles

  • Tokens first — color and spacing decisions flow Foundation → Theme → Component.
  • Accessible by default — text contrast, focus indicators, and non-color cues are required.
  • Public vs internal — consumers use public sets; .Base / helper components stay nested.
  • Figma is source of truth — if docs and Figma disagree, inspect the live file before changing product code.

How to use this documentation

  1. Start with Foundations and Tokens for architecture.
  2. Open a component section for purpose, states, and HTML previews.
  3. Check Accessibility before shipping.
  4. Confirm the live component in Figma via CURRENT_FIGMA_STATE.md.

Usage guidance

  • Foundation colors are raw palette values — no product meaning by themselves.
  • Prefer Theme / semantic tokens for surfaces, text, borders, and actions in product UI.
  • Component fills and strokes should come from Component tokens that alias through Theme.
  • Do not hard-code Foundation hex values in components unless intentionally documenting or building the palette itself.
  • Brand primary/secondary should not be changed casually — Theme and Component tokens depend on them.

Theme note: In the live file, color/action/primary/* resolves to neutral black/white. Brand red accent is on color/action/tertiary/* and Progress Bar fill. Do not assume Action buttons are brand red without checking Theme.

Usage guidance

  • Use display and heading styles for page and section hierarchy (Lora).
  • Use body styles for readable product content (Poppins Regular).
  • Use button / text-button styles for actions and compact UI labels.
  • Use caption styles for helper text, metadata, and secondary details.
  • Prefer applying text styles instead of manually overriding size, weight, or line height.
  • Do not detach text from styles for one-off sizing unless intentionally documented.

Accessibility guidance

  • Keep comfortable line height — Fukurou styles pair size with explicit pixel line heights.
  • Avoid relying on text smaller than caption for critical information.
  • Maintain hierarchy with style roles, not weight alone.
  • Handle contrast through Theme color tokens, not one-off text colors.
  • Avoid all-caps for long passages; Fukurou text styles use ORIGINAL case.

Tokens

Fukurou uses a 3-tier token model so product teams can retheme without rewriting components.

1. Foundation

Raw values: brand/neutral/status ramps, spacing, radius, shadow primitives. No product meaning.

2. Theme

Semantic decisions with Light/Dark: surface, text, border, action, status, elevation aliases.

3. Component

Component-specific hooks such as color/button/*, color/text-field/*, color/progress-bar/*.

Supporting collections: 2. Density and 2. Layout. Collection names must stay as numbered in Figma — do not rename to Primitive/Semantic.

Public

Calendar navigation

Previous/Next month controls use the internal .Base / Calendar / Nav Button component (calendar-specific; visually inspired by Icon Button but not an Icon Button instance). In product code, give them accessible labels Previous month and Next month.

Do

Use Date Picker when users need to select one specific date. Provide a visible label or accessible name. Keep the calendar popover separate from the closed trigger so layout does not reserve empty popover space.

Don’t

Don’t use this for date ranges. Don’t rely on placeholder or the calendar icon as the only label. Don’t recreate Multi-Select Dropdown or Date Range Picker from older templates.

A11y: Visible label or accessible name required. Associate error text in product code. Focus Visible must stay unclipped. Keyboard users should open the calendar, move between days, select, and close (Escape). Disabled dates are non-interactive (Exempt / Disabled state for contrast). Announce the selected date to assistive technology. Docs example uses semantic buttons for day cells; calendar icon is decorative (aria-hidden).

Tokens: color/date-picker/* · color/calendar/* · elevation/calendar/default · density/calendar/*. Internal: .Base / Calendar / Day Cell · .Base / Calendar / Nav Button. Supporting: Calendar Popover.

Accessibility

Fukurou targets WCAG 2.2 Level AA for token and component contrast. Latest tracked audit: 474 pairs · 0 non-exempt failures · 20 exempt disabled · 8 decorative (2026-07-26).

Contrast

  • Normal text ≥ 4.5:1
  • Large text ≥ 3:1
  • Meaningful icons, UI boundaries, focus indicators ≥ 3:1
  • Disabled / inactive controls: mark as Exempt / Disabled state — do not count as non-exempt failures

Focus visible

Keyboard focus must show a visible offset ring. Form controls that use an Active editing state still need a separate Focus Visible treatment (:focus-visible). Do not clip focus rings with parent overflow: hidden.

Keyboard & semantics

  • Icon-only controls need accessible names.
  • Error messaging must be text (not color alone) and associated programmatically.
  • Progress must expose current/min/max values and a text label.
  • Modals: focus trap, Escape, inert background.

Details: ACCESSIBILITY_AUDIT.md · fix plan: SAFE_WCAG_FIX_PLAN.md. Do not claim a live WCAG pass unless the audit against current tokens passed.

Guidelines

Public vs internal components

KindExamplesGuidance
Public setsButton, Text Field, Progress Bar…Publish for designers/engineers

Standalone helpersDropdown Menu, Modal Overlay, Cursor Line, Calendar PopoverSupporting pieces — prefer not to expose as primary library entries

When to use what

  • Button for actions; Text Button for low-emphasis text actions; Jumbo Select for choosing an option.
  • Snackbar for temporary feedback; Alert for persistent notices.
  • Radio when all choices are visible and exclusive; Dropdown when space is limited.
  • Date Picker for a single date; Date Range Picker is not a current component.
  • Progress Bar for known completion; always include text.

Naming conventions

  • Collections: 1. Foundation, 2. Theme, 2. Density, 2. Layout, 3. Component.
  • Component tokens: color/{component}/….
  • Internal components often prefix with .Base.

Removed / not current

  • Multi-Select Dropdown is not a current component.
  • Date Range Picker is not a current component (do not create unless explicitly requested).
  • Textarea, Tabs, and Tag / Chip are not in the live Figma file.
